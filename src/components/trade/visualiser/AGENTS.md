- AI layout pipeline: `AICuratedSceneSchema` (src/types/aiCuratedScene.ts) is the single contract between the layout generator and `AICuratedEnvironment`; financialSummary is always recomputed from curatedAssets via `summarise` so the ledger can't drift.
- AI layout prices come live from approved-member pricing (trade_product_pricing via source_pick_id, falling back to trade_products) plus effective_product_availability; unpriced pieces are Price upon Request and never placed — budgets reflect real RRPs.
- Saved AI layouts (ai_curated_layouts) are owner-only; clients read them solely via get_shared_ai_layout(token) when is_shared, from a frozen product snapshot (name, RRP, availability) — no owner identity or trade data leaks.
- Brief-to-layout curation lives in src/lib/curationEngine.ts: parse brief → style-token matrix (trade_products.design_style_tokens ∪ style_tags; untagged = neutral) → knapsack within the strict budget; it consumes fetchLiveCatalogue output only, so prices stay live approved-member RRPs.
- Cinematic walkthrough: the spline comes from useCinematicPath(scene) (elevated open arc validated against room limits and transformed 1.4m model bounds; smooth entry, steady cruise, synchronized OrbitControls on exit); active sessions keep editing/OrbitControls locked even when paused, explicit seek requests update the camera without resetting entry; restart/loop recaptures the current camera for a smooth entry, and speed scales the delta clock — pause/resume cannot jump. Playback keyboard shortcuts are active-session-only and ignore typing, native controls, modified keys and repeats. exportSceneToVideoAPI strips prices/budget before sending to the external render webhook (VITE_VIDEO_RENDER_WEBHOOK_URL; placeholder = dry run) — vendors get geometry, never trade figures.
- Custom camera paths (src/lib/customCameraPaths.ts) are node lists (position+target) built into the same CinematicPath contract, clamped to the room envelope; stored per layout (ai_curated_layouts.camera_paths), in the owner-only user_saved_camera_paths library, or localStorage cached_camera_path_<layoutId> — so preview and video export share one path shape.
- Walkthrough preferences (preset, custom path id, speed, loop) sync via the owner-only user_walkthrough_preferences row: account wins on load, localStorage is the offline fallback, writes are debounced after hydration so defaults never overwrite the account.
- Custom paths are never blocked, only warned: checkPathClearance tests the spline against the same 1.4m transformed furniture boxes presets use plus architectural anchor boxes (0.2m margin), so warnings and preset validation agree.
- Shared path menus and side-by-side comparison derive diagrams and durations from the same memoized CinematicPath as playback; durations include entry and speed so previews cannot drift, and comparison changes the route only on explicit selection.
- Generate Room Layout uses the deterministic src/lib/roomLayoutMatrix.ts (sofa centre, table 0.6m clearance in front, accent in emptiest perimeter quadrant, no overlap, strict budget) fed by fetchLiveCatalogue — same input gives the same scene, prices stay live.
- Room piece comparison (LayoutPieceCompare) is studio-only and derives trade prices via comparatorPrices with the viewer's tier discount — the same math as the Product Comparator; Client View hides the trade row through the data-trade-sensitive guard, and compare selection resets whenever the scene's piece list changes (index-based instance ids).
- AI architect layouts (ai-architect-layout edge function, admin-only) use the user's architect prompt verbatim; the model only proposes — validateArchitectLayout (src/lib/aiArchitectLayout.ts) re-checks bounds, overlaps, anchors, 0.6m coffee-table gap, POR exclusion and trade-cost budget (RRP less tier discount), and any break falls back to roomLayoutMatrix, so an AI slip never reaches the room.
- Walkthrough video fullscreen uses the native Fullscreen API on the existing player container, synchronized by fullscreenchange, with native video fullscreen on iOS; keeping the element mounted preserves playback and keeps the return control inside fullscreen.
- Angling a piece = placement yaw via PieceAngleControls (object.rotation[1]); ModelOrientationControls is collapsed "import repair only" — it tips the model itself and must never be the way users rotate pieces.
- Dragging is collision-aware: `resolveDragPosition` (visualiserPlacement.ts) pushes a dragged piece out of every other footprint (size × scale + margin); obstacles/selfRadius flow VisualiserCanvas → SceneObject via refs. The window drag-listener cleanup effect must stay mount-only (refs) — depending on dragMove/endDrag identity lets a parent re-render (e.g. selection) remove the live listeners and silently kill the drag.
- Finish sub-tabs are named from the product schema ("Table Top", "Base Structure") or the model's own mesh/material names via `humanizePartName` — never "Part 1/2/3"; the tab row is one scrollable horizontal track (`overflow-x-auto whitespace-nowrap scrollbar-none`), never wrapping.

- Visualiser render crashes are caught by SceneErrorBoundary and restore the last scene that rendered cleanly for 4s (visualiserSceneRecovery); a repeat crash within 30s resets to empty — prevents a crash loop.
- Shared comparisons reuse playback paths to avoid drift; preset switches blend poses and retain playback state.
- Advanced visualiser controls share visualiserAdvancedRendering mappings and persist with scenes/presets; contact opacity uses the same saved settings and DoF controls share the existing strength/toggle state. One Light multiplier scales key/environment and tightens bias, and joins raster/path-trace invalidation signatures so edits update both renderers. Hosted EXR pointers use the same environment loader in both modes.
- HDR toolbar and advanced menus share VISUALISER_ENVIRONMENTS and one persisted preference; texture commits wake the demand loop, and path tracing checks environment changes every frame even at its sample cap, so new reflections cannot remain stale.
- Depth of field shares a live furniture-bounds target; no selection uses nearest armchair/side-table depth band, while selection overrides it. Raster uses postprocessing and photoreal a PhysicalCamera, with focus-change-only resets. Portfolio defaults migrate once so later OFF choices persist; showroomRendering owns lens/grounding tokens and lens changes dolly the camera rather than moving furniture.
- Rug geometry and contact-shadow elevation share visualiserRug; the planar rounded surface uses high-resolution wool albedo plus linear tangent normals, preserving layout sizing/offsets while removing extruded piping. Legacy rug colours migrate once through rugSurfaceVersion so the requested cream replacement persists without moving furniture.
- ArchitecturalFeatureWall uses three lightweight PBR slabs with owned non-repeating maps; visualiserFeatureWall owns the finish list (travertine / microcement / raw concrete, unknown values fall back to travertine) plus per-finish roughness/bump/tint, and FeatureWallControls persists the pick with scenes/presets. Both renderers share the geometry, and uploaded photos suppress the wall (and disable the picker) to remain unobstructed. FeatureWallControls wraps its trigger in a focusable span with pointer-events-none while disabled so a tooltip can still explain the finish switch and the photo reason, and hides that tooltip while the picker is open.
- Marble coffee-table surfaces use visualiserMarbleProjection baked Y-axis planar UVs normalized across shared full-slab X/Z bounds and owned clamped map clones — raster and path tracing see one unmirrored slab across all rim faces and mesh quadrants without shader-only overrides, shared-asset mutation or base-finish changes.
- RugLayoutControls exposes persisted size/offset/degree rotation; RoomSurfaces rotates a centred Y-axis parent above the flat mesh so both renderers stay aligned without modifying furniture transforms.
- Coffee-table marble controls persist on each PlacedObject; visualiserMarbleSurface upgrades only owned marble tops to physical dielectric materials and updates them in place, preserving maps/geometry/bases and invalidating both renderers. Presets share paired settings in visualiserMarbleSettings and derive selection from saved values, so manual sliders and restored scenes cannot display a stale preset.
